# Sets clarify schema coverage and limits

Implementation follow-up, 2026-11-09: the bounded corpus analyzer and independent witness replay are now implemented. Both original research catalogs passed all 43 oracle expectations; 295 admitted official cases passed and 52 were explicitly excluded. The research-phase statements below about unexecuted examples describe the earlier baseline. See [current status](../STATUS.md) and [evidence](../EVIDENCE_LOG.md) for current scope and artifacts. Global feasibility, full-draft coverage and practical superiority remain unproved.

**MC/DC can inform JSON Schema coverage when the decision, condition occurrences and feasible inputs are declared explicitly; it does not transfer automatically to every keyword or to validator execution.** Accepted-instance sets give a sound model of validity under a fixed evaluation contract, and union, intersection, complement and exclusive regions recover the logical applicators' assertion behavior. Union alone is insufficient. More seriously, accepted-value sets discard annotation effects, so they do not justify unrestricted replacement of subschemas inside Draft 2020-12 contexts. This research proposes a strict semantic unique-cause pair criterion, derives its feasibility conditions, and supplies counterexamples and a bounded implementation handoff. Dependency-free finite checks passed **197314 assertions across 65808 Boolean-function/realizability models**; schema fixture expectations remain specification-derived and have not yet been executed against an independent validator. Practical usefulness, full-draft analysis and production implementation remain open work.

## Independence needs realizable pairs, not just outcomes

MC/DC is a structural coverage criterion rather than a single software product. NASA's public tutorial distinguishes unique-cause and masking approaches, discusses coupled condition occurrences, and situates structural analysis alongside requirements-based testing. It is a historical primary source, not a statement of current certification requirements. The project's schema criterion adopts an explicit unique-cause relation and omits program entry/exit obligations; it therefore needs a qualified name rather than a claim of certified program MC/DC. ([NASA tutorial, §§2.3.5, 2.5 and Appendix B](https://ntrs.nasa.gov/api/citations/20010057789/downloads/20010057789.pdf), [NIST glossary](https://csrc.nist.gov/glossary/term/Modified_condition_decision_coverage))

The following formalization is a project derivation. For feasible inputs X, condition vector c(x) and selected decision d(x)=f(c(x)), condition i has a strict witness pair x,y when its coordinate changes, all other selected coordinates remain equal, and the decision changes. Both endpoints must be actual inputs. For conjunction A∧B, vectors 11/01 witness A and 11/10 witness B. Merely observing 00 and 11 supplies both outcomes for every condition and for the decision, but supplies no strict independence pair. Conversely, changing several JSON fields is acceptable if only the target selected predicate outcome changes. This is a statement relative to the selected abstraction, not a causal claim about arbitrary input fields.

Condition occurrences matter. Two identical predicates under separate `anyOf` positions produce only 00 and 11; mixed vectors are impossible. Treating the positions as freely assignable Boolean variables invents witnesses. The familiar n+1 argument is also qualified: under strict unique cause, n distinct coordinate witness edges form an acyclic subgraph because a cube cycle must flip every used coordinate an even number of times. Hence at least n+1 distinct vectors are needed when all n obligations are feasible; a conjunction attains this bound. The argument does not guarantee feasibility or attainability for arbitrary constrained predicates, and it is not a general masking bound.

Open-source implementations offer useful comparison material. Clang documents `-fcoverage-mcdc` with source-based instrumentation and `llvm-cov` reporting; its current manual has version-dependent limits and stale six-condition wording, so installed-release behavior must be checked. LLVM 19.1.0 source retains vectors and finds independence pairs with don't-care handling. GCC exposes `-fcondition-coverage` and `gcov --conditions`; its manual explicitly describes masking MC/DC, and the implementation author's paper explains its CFG/BDD and runtime-mask approach. Those tools measure program structure, not interpreted-schema semantics. No compiler experiment was run here, and matching percentage labels would not establish equivalence of criteria. ([Clang manual](https://clang.llvm.org/docs/SourceBasedCodeCoverage.html), [LLVM 19.1.0 source](https://raw.githubusercontent.com/llvm/llvm-project/llvmorg-19.1.0/llvm/lib/ProfileData/Coverage/CoverageMapping.cpp), [Gcov manual](https://gcc.gnu.org/onlinedocs/gcc/Invoking-Gcov.html), [Kvalsvik's implementation report](https://arxiv.org/html/2501.02133v1))

## Draft 2020-12 preserves more than validity

The Core specification distinguishes assertions, annotations and applicators; the Validation specification defines constraints and vocabulary policies. Numeric assertions succeed on nonnumeric values, so `minimum:18` denotes all nonnumbers together with numbers at least 18. A `properties` subschema applies only to existing matching properties; absence does not create a false child outcome. `format` is annotation-oriented under the default vocabulary policy, with assertion behavior requiring explicit configuration; content and metadata keywords do not become ordinary Boolean validation conditions. These distinctions make a flat list of independently assignable keyword bits misleading. ([Core §§7, 10–11](https://json-schema.org/draft/2020-12/json-schema-core), [Validation §§6–9](https://json-schema.org/draft/2020-12/json-schema-validation))

The decisive counterexample is contextual. `{"properties":{"a":true}}` and Boolean `true` accept the same standalone values. Place either under `allOf` beside `unevaluatedProperties:false`. The instance `{"a":1}` passes with the first child and fails with the second because only the first supplies evaluated-property credit. Thus **acceptance equality is not a congruence for arbitrary schema contexts**. This original deduction refutes unrestricted composition using plain accepted-value sets; it does not refute whole-schema denotations or richer sets of evaluation states. The same mechanism means all successful `anyOf` branches can contribute annotations, while a failed branch cannot supply successful evaluated-name credit. ([Core §§7.7.1.2, 10.2.1.2, 11.3](https://json-schema.org/draft/2020-12/json-schema-core))

Other boundaries reinforce that result. `additionalProperties` uses adjacent property keywords and differs from `unevaluatedProperties` across composition. `contains` with count bounds and `unevaluatedItems` needs matching indices, not one existential bit. Conditionals select a branch rather than conjoining all branches. `$ref` siblings remain active, and `$dynamicRef` can depend on dynamic scope. Invalid schemas, unsupported vocabularies, unresolved resources and undefined or unfinished recursive evaluation cannot be silently encoded as validation false. The detailed keyword inventory covers all standard families and identifies observations or explicit deferrals. Official suite files provide primary behavioral examples, but their moving URLs must become immutable commit pins before experiments. ([Core §§8.2.3, 9.4, 10–11](https://json-schema.org/draft/2020-12/json-schema-core), [official test suite](https://github.com/json-schema-org/JSON-Schema-Test-Suite))

## Set algebra yields a qualified coverage model

Fix a contract E containing dialect, vocabularies, registry, numerical model and format policy, plus occurrence context κ. Assuming well-formed, supported, resolved and terminating evaluation, define ⟦S⟧E,κ={x∈J: S validates x}. This definition projects evaluation onto validity. For compatible children at one location, `allOf` is intersection, `anyOf` union and `not` complement. `oneOf` is the union of regions Aᵢ∖⋃ⱼ≠ᵢAⱼ. Binary `oneOf` equals symmetric difference; three-way symmetric difference means odd parity and is wrong for exactly-one. Three `true` children furnish the smallest clear counterexample: exactly-one accepts nothing, while odd parity accepts everything. These are project membership proofs of the specification's logical requirements. ([Core §10.2.1](https://json-schema.org/draft/2020-12/json-schema-core))

For declared conditions A₁…Aₙ, each truth vector b defines cell R_b=⋂ᵢ(Aᵢ if bᵢ=1, otherwise J∖Aᵢ). Nonempty cells partition the domain. A strict witness for coordinate i exists precisely when two adjacent cells R_b and R_b⊕eᵢ are both nonempty and f changes across them. The proof is direct: a concrete pair identifies adjacent cells; conversely, one member of each nonempty adjacent cell supplies a pair. Boolean sensitivity alone is insufficient because it ignores realizability. This exact equivalence is the proposed criterion's foundation, while deciding cell nonemptiness remains a separate computational problem.

For conjunction, define positive region P=⋂ⱼAⱼ and negative exclusive region Nᵢ=(⋂ⱼ≠ᵢAⱼ)∖Aᵢ. Independence requires both P and Nᵢ nonempty. For disjunction it requires both the all-false region J∖⋃ⱼAⱼ and the exclusive positive region Aᵢ∖⋃ⱼ≠ᵢAⱼ. One exclusive instance is therefore insufficient. For exactly-one, toggling a condition changes the decision only when the other conditions contain zero or one true result, again subject to realizable endpoints. Redundant minima, duplicate alternatives, contradictions and constant branches demonstrate the failures that an implementation must retain.

Define C(T) as obligations witnessed by pairs with both endpoints in suite T. C is monotone under adding tests, but C(T∪U) can exceed C(T)∪C(U) when endpoints come from different suites. Consequently, merging coverage summaries requires vectors or endpoint evidence, not just unioning previously covered IDs. Minimization is likewise pair-aware: selecting an obligation's pair requires selecting both tests, and minimizing pairs differs from minimizing distinct tests because endpoints can be shared. The chapter supplies a finite binary optimization model; no practical optimizer or optimality claim exists yet.

## Bounded implementation can preserve honest evidence

The recommended first implementation handles a pure, acyclic fragment: Boolean schemas, type/equality assertions, selected numeric bounds and logical applicators, using immediate child outcomes as conditions of each local logical decision. References, conditionals, structural object/array/string assertions, formats and annotation-sensitive semantics are explicit deferrals. Local decision influence must remain separate from root influence. A local `anyOf` under an outer false conjunction can flip while the root never changes. This deliberately bounded catalog is useful only when its omissions and decomposition are visible.

Every credited obligation needs concrete endpoint IDs, vectors, local outcomes, contract identity and independent oracle replay. Reports distinguish covered, feasible but uncovered, proven infeasible, unknown and unsupported. An exhaustive finite pool can prove absence only within that pool; it cannot justify an all-JSON infeasibility claim. Unknown and unsupported obligations remain visible in denominators, and zero obligations produce N/A. A feasibility-adjusted percentage can exclude only proofs in the score's stated universe. The handoff specifies identities, parsing/equality rules, deterministic generation, pair-aware selection, error handling, planned CLI commands and review gates.

The finite research script checks exactly-one identities and toggle characterizations through four predicates, and pair-versus-adjacent-cell equivalence for every Boolean function and realizable-cell subset through three predicates. Its recorded 197314 successful assertions across 65808 models were independently rerun during coordination. Both JSON fixture catalogs passed syntax checks, but no independent validator run occurred. These checks support the algebra; they do not show full-draft conformance, unbounded solver completeness, generation scalability or superior defect detection. Later experiments must pin validator/tool versions and test-suite commits, replay witnesses, compare equal-budget baselines and preserve negative findings.

## Implications for the next stage

The immediate engineering opportunity is a tool that exposes missing evidence rather than forcing every schema into a percentage. A sound finite witness analyzer can be useful even when global feasibility remains unknown, provided domain and decomposition travel with every result. Expansion should follow a richer observation model where needed, especially evaluated locations and reference context, instead of weakening the definitions to accommodate unsupported cases.

The experiment's practical value remains falsifiable. If pair coverage improves neither fault discovery nor test efficiency under fair comparisons, that is a legitimate research outcome. The repository now supplies the mathematical contract and counterexamples needed to investigate that question without mistaking an elegant set representation for a validated testing method.
