# Uncertainties and evidence boundaries

Implementation follow-up, 2026-11-09: the bounded corpus analyzer and independent witness replay are now implemented. Both original research catalogs passed all 43 oracle expectations; 295 admitted official cases passed and 52 were explicitly excluded. The research-phase statements below about unexecuted examples describe the earlier baseline. See [current status](../STATUS.md) and [evidence](../EVIDENCE_LOG.md) for current scope and artifacts. Global feasibility, full-draft coverage and practical superiority remain unproved.

Research checked 2026-11-08. Distinguish source-backed semantics, project definitions, mathematical deductions, finite checks and future empirical claims.

| Question | Current evidence | Required next evidence |
|---|---|---|
| Is this standard program MC/DC? | No. NASA motivates an explicit schema semantic unique-cause relation. | Keep naming qualified; do not claim certification or current regulatory compliance. |
| Does every schema admit an independent pair per condition? | No. Duplicate predicates, redundant conjuncts and constant decisions supply counterexamples. | Preserve infeasible obligations with proof and domain. |
| Are arbitrary accepted sets compositionally sufficient? | No. Equal standalone acceptance can produce different parent validity through evaluated-location annotations. | Add richer evaluation semantics before supporting annotation-sensitive parent influence. |
| Can all relevant cells be decided? | No general solver or decidability theorem was established. | Start with finite candidate domains; any global proof must name a sound supported fragment. |
| Were schema examples run? | JSON syntax was checked; expectations were derived from specifications. No independent validator was available during research. | Pin an oracle and execute both fixture catalogs before regression claims. |
| What did finite checks prove? | 197314 assertions over 65808 finite Boolean-function/realizability models passed. | They do not establish full-draft conformance, performance or fault detection. |
| Do coverage tools agree? | LLVM and GCC source/manuals were inspected; GCC calls its criterion masking. LLVM manuals contain version-dependent limits and stale wording. | Pin releases and run explicit-vector experiments before comparing outputs. |
| Is the proposed coverage useful? | Unknown. Mathematical soundness of a declared pair criterion does not imply practical benefit. | Compare coverage, costs and mutation outcomes under equal budgets. |
| Are references and recursion solved? | Relevant spec and official suite cases were inspected; no general evaluator was built. | Defer in MVP; later define dynamic context identity and termination/error policy. |
| Are versions reproducible? | Draft specification URLs and one LLVM tag are fixed; other manuals and suite URLs move. | Freeze source SHAs, tool versions, configurations and content digests before implementation experiments. |

The research did not obtain current RTCA standards, build compilers, audit complete coverage-tool implementations, select an instrumentation API, prove a full denotational semantics, implement an analyzer, or measure scalability. Unknown, unsupported, invalid input, unresolved reference, resource exhaustion and ordinary validation failure must remain distinguishable.

A missing witness from a finite corpus proves only absence within that corpus. A mathematical argument can prove more only under its stated assumptions. A zero-obligation result is N/A, not 100%. A local decision flip does not establish root influence.
